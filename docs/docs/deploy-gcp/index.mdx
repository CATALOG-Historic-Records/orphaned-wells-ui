# Deploy to GCP

OGRRE production deployments use three pieces of Google Cloud infrastructure:

| Layer | Source | Purpose |
| --- | --- | --- |
| Terraform | `orphaned-wells-ui-server/deployment/terraform` | Creates and manages backend cloud infrastructure, including GKE Autopilot, upload buckets, static IPs, and DNS records. |
| Kubernetes on GKE | `orphaned-wells-ui-server/deployment/kubernetes` | Runs one backend workload per collaborator in the shared GKE cluster. |
| App Engine | `orphaned-wells-ui/deployment/app-engine` | Serves one frontend App Engine service per public collaborator deployment. |

The backend deployment path is GKE Autopilot. Legacy Compute Engine VM modules and definitions have been retired from Terraform; the old VM runtime assets are available only through Git history.

## Standard deployment order

1. Confirm the [Google Cloud service accounts](/docs/install/gcp_setup#create-google-service-account-keys) and [GitHub secrets](/docs/deploy-gcp/github-secrets) prerequisites.
2. Add the collaborator to `terraform.tfvars` (`./deployment/terraform/scripts/sync_tfvars.sh push --secret`) and `collaborators.json`, then merge to `main` and approve the `terraform-apply` gate in GitHub Actions (see [Terraform Infrastructure](/docs/deploy-gcp/terraform)).
3. Push the collaborator branch to deploy the [backend on GKE](/docs/deploy-gcp/backend-gke) (which automatically provisions the collaborator's MongoDB Atlas database/user on first deploy and saves the active `.env` snapshot to GCS).
4. Configure `BACKEND_URL`, `collaborators.json`, and `dispatch.yaml` in the frontend repo and push the collaborator branch to deploy the [frontend on App Engine](/docs/deploy-gcp/frontend-app-engine).
5. Configure frontend Cloud DNS records, the App Engine custom domain, and the Google OAuth origin/redirect URI.
6. Verify the backend `/health` endpoint, frontend App Engine service, and OAuth sign-in flow.
